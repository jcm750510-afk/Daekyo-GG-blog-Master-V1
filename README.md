# GPT용 눈높이 블로그 프롬프트 마스터 V2

대교 눈높이 교육 콘텐츠를 위한 **GPT 기반 블로그 주제 추천 + 블로그 작성 프롬프트 생성 웹앱**입니다.

이 프로젝트는 GitHub Pages에서 동작하는 정적 React/Vite 웹앱으로 구성되어 있으며, **Gemini API를 사용하지 않습니다.**

## 핵심 운영 방식

```text
사용자
  ↓
GitHub Pages 웹앱
  ↓
① 학습자·과목·제품·지역·포스팅 유형 입력
  ↓
② GPT용 '주제 10개 추천 프롬프트' 자동 생성
  ↓
③ ChatGPT에서 서로 다른 주제 10개 생성
  ↓
④ 생성된 10개 주제를 웹앱에 붙여넣기
  ↓
⑤ 주제 선택
  ↓
⑥ GPT용 최종 블로그 작성 프롬프트 자동 생성
  ↓
⑦ ChatGPT에 붙여넣어 블로그 작성
```

### 왜 GPT 방식으로 변경했는가?

GitHub Pages는 정적 웹 호스팅이므로 웹앱에 Gemini/OpenAI 등의 API 비밀키를 넣어 브라우저에서 직접 호출하는 방식은 보안과 운영 측면에서 적합하지 않습니다.

현재 V2는 **AI 모델 호출을 웹앱에 직접 넣지 않고, GPT가 수행해야 할 작업을 고품질 프롬프트로 자동 설계하는 방식**으로 변경했습니다.

따라서:

- Gemini API 키가 필요하지 않습니다.
- GitHub Secrets에 AI API 키를 저장하거나 빌드에 주입하지 않습니다.
- 사용자의 API 키가 GitHub 저장소에 노출될 가능성을 제거했습니다.
- 주제 생성은 사용자가 사용하는 ChatGPT 환경의 GPT가 담당합니다.
- 웹앱은 입력값과 눈높이 콘텐츠 지식을 결합하여 GPT용 프롬프트를 자동으로 만들어 줍니다.

## 현재 웹앱 기능

### STEP 1. 콘텐츠 조건 입력

다음 정보를 입력합니다.

- 타겟 독자: 영유아, 유아, 예비초, 초1~초6, 중1~중3, 고1, 시니어
- 과목/학습영역: 수학, 국어, 영어, 창의독서·문해력, 한자, 사회, 과학, 어휘력, 학습습관, 기타
- 추천 제품
- 지역/러닝센터명
- 포스팅 유형
- 이미지 스타일
- 원장님 요청사항

입력값은 이후 주제 추천 프롬프트와 최종 블로그 프롬프트에 모두 반영됩니다.

### STEP 2. GPT 주제 10개 추천

웹앱이 다음 조건을 포함한 GPT용 주제 추천 프롬프트를 자동으로 만듭니다.

- 학년/연령
- 과목
- 제품
- 지역
- 포스팅 유형
- 현재 계절/학사 시기
- 과목별 주제 방향
- 눈높이 콘텐츠 지식 기준
- 학부모 검색 의도
- 교육 90 : 홍보 10 원칙
- 주제 간 중복 방지
- 구체적인 학부모 고민 중심

`GPT 프롬프트 복사` 또는 `ChatGPT 열기`를 이용해 GPT에게 10개 주제를 요청합니다.

GPT가 생성한 결과를 웹앱의 입력창에 붙여넣으면 번호가 붙은 목록 또는 JSON 배열을 자동으로 인식합니다.

### STEP 3. 최종 블로그 프롬프트

선택한 주제와 입력 조건을 이용하여 GPT용 최종 블로그 작성 프롬프트를 생성합니다.

최종 프롬프트에는 다음 내용이 포함됩니다.

- 타겟 독자
- 과목/학습영역
- 추천 제품
- 핵심 주제
- 지역/러닝센터
- 포스팅 유형
- 이미지 스타일
- 원장님 요청사항
- 계절/시기
- 교육 90 : 홍보 10
- A.E.A 구조
- 이미지 제작 가이드
- SEO 제목 후보
- 본문
- 소제목별 핵심 포인트
- 상담 CTA
- 네이버 블로그 해시태그

## GPT 주제 추천 프롬프트의 설계 원칙

GPT에게 단순히 '주제 10개를 만들어줘'라고 요청하지 않습니다.

다음 순서로 주제를 기획하도록 프롬프트를 구성합니다.

1. 타겟 학습자의 학년/연령 확인
2. 과목의 핵심 학습요소 확인
3. 현재 시기와 학사 일정 반영
4. 학부모의 실제 고민과 검색 의도 도출
5. 문제 원인·체크리스트·실천법·오개념·학습습관·학년 전환 등 관점 분산
6. 제품/센터 홍보는 최소화
7. 서로 다른 10개 주제로 중복 제거
8. 네이버 블로그에서 바로 사용할 수 있는 자연스러운 제목 형태로 출력

## GitHub Pages 배포

저장소의 GitHub Pages Source는 **GitHub Actions**로 설정합니다.

`main` 브랜치에 변경사항이 push되면 다음 workflow가 자동 실행됩니다.

```text
.github/workflows/deploy-pages.yml
        ↓
npm ci
        ↓
npm run build
        ↓
GitHub Pages artifact 생성
        ↓
GitHub Pages 배포
```

Vite의 프로젝트형 GitHub Pages 주소에 맞춰 `vite.config.ts`의 `base`는 다음과 같이 설정되어 있습니다.

```ts
base: '/Daekyo-GG-blog-Master-V1/'
```

## 보안 원칙

현재 웹앱에는 Gemini/OpenAI API 키를 넣지 않습니다.

특히 다음과 같은 방식은 사용하지 않습니다.

```text
브라우저
  ↓
API_KEY 직접 포함
  ↓
AI API 호출
```

정적 GitHub Pages에서 비밀키를 브라우저 코드에 포함하면 사용자에게 노출될 수 있기 때문입니다.

향후 웹앱 자체에서 버튼 하나로 AI가 자동 생성하고 결과까지 받아오는 완전 자동화가 필요할 경우에는 다음 구조로 확장하는 것이 적절합니다.

```text
GitHub Pages
     ↓
별도 서버리스/Edge API
     ↓
OpenAI API
     ↓
GPT 주제 10개
     ↓
웹앱으로 반환
```

이 경우에도 OpenAI API 키는 브라우저가 아니라 서버 측 환경변수/Secret으로 관리합니다.

## V2 변경사항

- Gemini API 기반 주제 생성 기능 제거
- Gemini API 키 입력 UI 제거
- Vite의 `GEMINI_API_KEY` 빌드 주입 제거
- GitHub Actions의 Gemini Secret 전달 제거
- GPT 주제 추천 프롬프트 자동 생성 기능 추가
- ChatGPT 바로 열기 기능 추가
- GPT 결과 10개 붙여넣기 및 자동 파싱 기능 추가
- 주제 선택 후 최종 GPT 블로그 프롬프트 자동 생성
- README를 현재 GitHub Pages + GPT 운영 방식에 맞게 전면 개편

## 향후 V3 확장 방향

완전 자동화를 원한다면 다음 기능을 추가할 수 있습니다.

1. 웹앱에서 `GPT로 10개 추천` 버튼 클릭
2. 서버리스 API가 OpenAI API 호출
3. GPT가 10개 주제 반환
4. 웹앱에 주제 카드 10개 자동 표시
5. 사용자가 주제 선택
6. 동일한 API를 통해 최종 블로그 초안까지 자동 생성

이 단계에서는 API 키를 서버 측에서 관리하는 구조를 사용해야 합니다.
